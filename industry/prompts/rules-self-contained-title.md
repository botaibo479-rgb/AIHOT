
【标题自洽规则 — 让读者不点开就知道"这是关于谁的什么事"】

1. 标题必须点出核心主体：标的代码 / 公司名 / 项目名 / 机构名。
2. 原标题已经清楚点出主体的：英文标题翻译成中文、中文标题保持原意，不要为改写而改写。
3. 原标题只是版本号 / 代号 / 没信息量的 teaser（如 "Update"、"Announcement"、"Notice"、"重磅"）时，结合【来源】和正文把主体补进标题。例：原标题 "Notice on Delisting" + 来源 "Binance：公告" + 正文列出了代币 → "币安公告将下架 XXX 现货交易对"。
4. 补主体只能用【来源】或正文里真实出现的名字。正文和来源都没点出具体型号时，用上位词（如"某代币""某上市公司"）兜底，绝不凭"行业常识"编一个具体代码 / 日期 / 数字。
5. 原标题表达的【文章类型和核心动作】是硬边界：How / Why / Analysis / Outlook / Review 这类解释、分析、展望或复盘标题，中文标题必须保留这个类型；不能因为正文谈到一个已经存在的规则、公告或新数据，就改写成“宣布 / 批准 / 生效 / 上线”。只有原标题明确宣布了公告、批准、生效或上线，中文标题才能使用对应动作。保留文章类型不等于删主体：仍须按第 1-4 条补全正文或来源明确给出的标的、公司、机构名。
   例：原标题 "Why the ETH unlock matters" → "以太坊这次解锁为何值得关注"，不能写成 "以太坊宣布解锁"。
   例：原标题 "What the new listing rules mean" + 来源和正文明确是港交所 → "港交所新上市规则的影响解读"，不能只写成缺主体的 "新上市规则的影响"。
6. 本条的动作和背景里的旧公告要分清：原文把公告写成过去的事（“Last week we announced …”“上周我们公布了…”），本条是在提醒、解读或再次推广时，标题写提醒、解读或回顾，把公告交代成此前的事；不能写成“宣布 / 公布 / 上线”，否则读者会当成今天的新闻。只有原文明确某项规则是现在才生效或新增，才对那一项用对应动作。
   例：正文 "Last month we announced the buyback program … Here is how it works" → "某项目讲解上月公布的回购机制"，不能写成 "某项目宣布回购"。
